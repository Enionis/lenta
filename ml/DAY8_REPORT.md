# Day 8 — Переобучение YOLO на чистых GT-позитивах

## Идея

День 1 учил YOLO на ~12500 псевдо-bbox от HSV-эвристики — это «грязный» сигнал, ловящий красные пятна на упаковках. Сейчас у нас есть 157 GT-bbox из 3 размеченных видео — это идеальный сигнал. С расширением ±3 кадра вокруг каждого получили **179 кадров × 1044 bbox** реальных ценников.

## Что сделано

### 1. `build_gt_dataset.py` — новый чистый датасет
- Для каждой GT-строки (3 видео × 57+71+29 = 157 ценников) извлекаем кадр в `frame_timestamp`, а также ±3 соседних кадра с тем же bbox.
- Ресайз 4K → 1920 long-side, пересчёт bbox.
- Train/val split 85/15. Класс один — `price_tag`.
- Итого: **179 кадров, 1044 bbox** в `ml/output/yolo_dataset_gt/`.

### 2. Fine-tune от v1 → v2
- `train_yolo.py --model pricetag_v1/best.pt --epochs 20` (warm start от текущей модели).
- 20 эпох на MPS, ~4 минуты.
- Метрики на val (179 кадров): P=0.625, R=0.663, mAP@0.5=0.677.
- Внешне ниже v1 (P=0.90, mAP=0.956), но v1 училась на овер-плотных HSV-метках — её метрика искусственно высокая.

### 3. Sanity check на GT-bbox (детектор без всего остального)

| Видео     | v1 recall | v2 recall   | Δ      |
|-----------|-----------|-------------|--------|
| 25_12-20  | 40.4%     | **73.7%**   | +33%   |
| 26_12-20  | 57.7%     | **70.4%**   | +13%   |
| 43_15     | 65.5%     | **93.1%**   | +28%   |

Среднее **+25 пп recall детектора**. Это прямой выигрыш в количестве распознанных ценников.

### 4. End-to-end метрики

| Видео     | F1 (7→8)          | P (7→8)         | R (7→8)         | TP (7→8) |
|-----------|-------------------|-----------------|-----------------|----------|
| 25_12-20  | 0.091 → **0.182** | 0.13 → **0.67** | 0.07 → 0.11     | 4 → 6    |
| 26_12-20  | 0.263 → **0.362** | 0.27 → **0.74** | 0.25 → 0.24     | 18 → 17  |
| 43_15     | 0.296 → **0.480** | 0.32 → **0.57** | 0.28 → **0.41** | 8 → **12** |

**Precision вырос драматически** (0.27 → 0.74 на 26_12-20): v2 даёт намного меньше false positives.

Per-field на сматченных:
- color: 24/35 = **69%** (стабильно)
- discount: 6/35 = 17%
- price_card: 8/35 = **23%** (на 43_15: 6/12 = **50%**)

### 5. Артефакты обновлены
- `ml/pipeline.py` теперь использует `pricetag_v2/best.pt` по умолчанию.
- `detect_and_track.py` тоже.
- ONNX: `ml/output/runs/pricetag_v2/weights/best.onnx` (12 MB).

## Что заметно улучшилось

- **Precision поднялся в 3–5 раз** — v2 почти не ловит бутылки/полки.
- **F1 вырос на всех 3 видео.**
- **43_15 теперь F1 = 0.48** — почти половина строк попадает в evaluator.

## Что не улучшилось / новые проблемы

- **Recall на 25_12-20 всё ещё низкий** (0.07 → 0.11). Sanity-check показывал 73%, но фильтр «должна быть цена» режет до 9 строк (vs 57 GT). Видимо OCR не справляется с большинством crop'ов в этом видео (мелкие, повёрнутые, через стекло).
- **Recall на 26_12-20 чуть просел** (0.25 → 0.24): v2 строже, conf=0.25 фильтрует часть истинных позитивов. Снижение до conf=0.15 на день 9 поднимет.

## План на день 9

1. **Подбор conf** per-video или общий: conf 0.15 на 25_12-20 и 26_12-20 должен поднять recall.
2. **Tiling inference** на 4K: 2×2 patches с overlap 20% → +10-15% recall на мелких ценниках.
3. **YOLOv8s warmstart с pricetag_v2.pt** + объединённый датасет (псевдо + GT) для финальной модели.

## Команда воспроизведения

```bash
source .venv/bin/activate
SSL_CERT_FILE=$(python3 -c "import certifi;print(certifi.where())")

# 1) Сформировать GT-датасет
python3 ml/scripts/build_gt_dataset.py --neighbor_frames 3

# 2) Fine-tune от v1
python3 ml/scripts/train_yolo.py \
  --model ml/output/runs/pricetag_v1/weights/best.pt \
  --epochs 20 --imgsz 960 --batch 12 --name pricetag_v2

# 3) Полный пайплайн (уже использует v2)
python3 ml/pipeline.py /path/to/video.mp4 --out result.csv

# 4) Метрики
python3 ml/scripts/evaluate_final.py
```
