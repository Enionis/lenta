# Day 5 — ML/CV: финальная подгонка качества

## Что сделано

### 1. Font-size-aware парсер цен
- `run_ocr_qr.py`: для каждого OCR-токена сохраняется bbox-height (прокси размера шрифта).
- `build_final_csv.parse_prices`: сортируем токены с числами по высоте; самый крупный шрифт → `price_card` (со скидкой/по карте, обычно крупная цифра), второй по размеру → `price_default` (старая, мельче).
- Дополнительно склеиваем соседние токены `{rub}` + `{kop}` если их высоты близки (±50%): `679` + `99` → `679.99`.
- Эвристика обмена: если `price_default < price_card` — меняем местами (карта всегда дешевле).
- Защита от мусора: одиночные числа принимаются только в диапазоне `[10, 99999]`.

### 2. Дедупликация дублей (`build_final_csv.py`)
- Группировка pred-строк по `bbox overlap ≥ 0.5` и `|Δts| ≤ 500 ms`.
- В каждой группе оставляем строку с большим bbox (чёткий best frame).
- На 25_12-20: 27 → 26 rows; на остальных не было дублей.

### 3. Точный regex скидки
- `[-]?\s?([1-9]\d)\s*%` — только двузначная скидка (10–99%).
- Убрал ложные срабатывания на одиночных «5%» и «1%» (которые путали с обрывками цифр).

## Что не сложилось и почему

- **Цены matched=0/X на сматченных строках.** Spatio-temporal матчер находит пары pred↔GT правильно по bbox+ts, но конкретный pred-крип содержит не ту цену, что в GT. Причина: наш best-frame отстаёт/опережает GT-best-frame на 100–500 ms, за это время робот сместился и в кадре оказался соседний ценник с другой ценой. Это **системная** проблема выбора best-frame, не парсера.

  Фикс на день 6+: вместо одного best-frame брать **топ-3 кадра по area×sharpness**, OCR'ить каждый, объединять результаты — устойчивее к смещениям.

- **Barcode = 0.** Подтверждено в день 4: видео физически не позволяет декодировать (cv2 / zxing / pyzbar — все 0). Только спец-ML.

- **id_sku, print_datetime = 0.** Мелкий текст внизу ценника не доходит до OCR даже после upscale ×2 и allowlist-фильтра. Нужен либо более сильный OCR (PaddleOCR PP-OCRv4 server-версия), либо ML-модель распознавания цифр под штрихкодом.

## Финальный pipeline.py — что отдаём

```python
from ml.pipeline import PriceTagPipeline
df = PriceTagPipeline().process_video("/path/to/video.mp4")
df.to_csv("result.csv", index=False, encoding="utf-8",
          quoting=csv.QUOTE_MINIMAL)
```

Конвейер end-to-end:
1. YOLOv8n (best.pt, 5.9 MB, mAP@0.5=0.956) + ByteTrack
2. Фильтр коротких треков + cross-track NMS
3. High-res crop из оригинального 4K кадра (padding 18%)
4. EasyOCR ru+en, 4 ориентации, tile-OCR для нижней трети
5. cv2.barcode + cv2.QR + zxing на crop'е и на полном кадре
6. Font-size-aware парсер цен, regex для скидки/даты/штрихкода
7. HSV-классификатор цвета
8. Дедуп ±500 ms + IoU 0.5 → один pred на ценник

## Известные ограничения

1. **Промежуточные файлы по stem'у видео** — два видео с одинаковым именем перетирают друг друга. Backend должен передавать каждое видео в отдельную рабочую директорию (или мы добавим в pipeline.py).
2. **Время обработки**: 60-сек видео @ 4K → ~3–5 мин на CPU/MPS. RKNN int8 на роботе должен дать ~10×.
3. **product_name пусто** — нужен локальный LLM (Qwen 2.5 3B Q4) или whitelist каталога.
