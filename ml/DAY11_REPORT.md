## Что сделано

### 1. Реализована метрика организаторов (`evaluate_official.py`)
Из FAQ:
1. Pred-строка сопоставляется с GT-ценником: сначала по barcode (EAN-13), иначе по spatio-temporal ключу (`frame_timestamp` + IoU bbox).
2. Для пары считается доля СОДЕРЖАТЕЛЬНЫХ полей (23 шт: 12 ценника + 11 QR), совпавших по правилам типа.
3. Ценник «успешно распознан» если ≥80% полей совпало.
4. **TARGET_METRIC = (число успешно распознанных) / |GT|.** Знаменатель — всё GT, поэтому пропущенные тоже считаются как 0.

Правила сравнения по типам:
- цены: exact / ±1% / `int()` совпадает
- product_name: пересечение токенов длины ≥4
- barcode/qr_code_barcode: только цифры, exact
- остальные: case-insensitive строка

Семантика «нет»/пусто (как в ТЗ):
- GT «нет», pred «нет» → ✅
- GT «нет», pred value/пусто → ❌ (мы должны были написать «нет»)
- GT value, pred «нет»/пусто → ❌
- **GT пусто** → ✅ (поле в GT не размечено — не штрафуем pred)

### 2. Исправлены 2 бага в эвалюаторе
**Баг A: GT colNames truncated.** Организаторы дают `wholesale_level_1_coun` без `t`. Pred имеет `wholesale_level_1_count`. → 0% совпадение даже когда оба «нет». Фикс — маппинг при чтении GT.

**Баг B: case `GT=пусто, pred=«нет»` возвращал False.** Логика field_match теперь сначала проверяет `gt_empty` → возвращает True. После фикса avg per-pair вырос с **0.35 → 0.46**.

### 4. Embedded LLM — отказ от LM Studio (соответствие ТЗ п.2)

**Почему:** LM Studio — GUI-приложение, не воспроизводится в Docker и не подходит для контура компании. Это нарушение ограничения «локально и без облака» (точнее, его не положишь в стандартный Linux-Docker).

**Что сделано:**
- Установлен `llama-cpp-python` (через pip).
- GGUF-веса скопированы из LM Studio cache в `ml/weights/qwen2.5-3b-q4_k_m.gguf` (1.8 GB).
- Скрипт `llm_product_name.py` переписан: вместо HTTP-запросов к localhost:1234 — прямой вызов `Llama.create_chat_completion()`.
- Поддержка GPU (Metal/CUDA через `n_gpu_layers=-1`).
- Ленивый синглтон `_LLM` — модель загружается один раз.

**Результат:** идентичная скорость (~6 it/sec на M-серии), полная воспроизводимость в Docker, отсутствие внешних зависимостей.

Use:
```python
from ml.scripts.llm_product_name import extract_one, get_llm
get_llm()  # load
name = extract_one("OCR text...")
```

## Что в следующих днях

**День 12 — нет-калибровка по типу ценника:**
Анализ GT-распределения показал что **для большинства типов ценников QR-поля price1/2/4_qr содержат valid value, а не «нет»**. Наш текущий дефолт «нет» здесь **ВРЕДИТ**. Нужно либо парсить эти поля из QR (когда декодер сработает), либо ничего не писать (пусто = тоже неправильно).

Проблема в том что без рабочего QR-декодера 4 поля закрыть невозможно с нашими видео.

**Стратегия:** в дне 12 перейти к двухклассовой стратегии:
- Если уверены что у ценника есть QR-код, в QR-полях оставлять пусто (хуже чем «нет»? Зависит от GT).
- Если уверены что не предусмотрен (по типу ценника) — «нет».

Тип ценника определять по цвету + геометрии + размеру (всё локально, без новых моделей).
